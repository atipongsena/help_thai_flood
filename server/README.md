# Flood Aid API (Phase 1)

Minimal Express + TypeScript backend that exposes case endpoints for the flood-aid dashboard.

## Prerequisites

- Node.js 20+
- MongoDB instance (Atlas/local)

## Setup

```bash
cd server
cp .env.example .env        # update secrets
npm install
```

## Development

```bash
npm run dev
```

## Seeding sample data

```bash
npm run seed
```

The seeder reads `../data/all_posts_raw.csv` (generated by `training/prepare_dataset.py --export --sos`) and imports a subset into MongoDB.

## Routes

| Method | Path                     | Description                                  |
| ------ | ------------------------ | -------------------------------------------- |
| GET    | `/health`                | Health check                                 |
| GET    | `/api/cases`             | List cases (priority/status filter)          |
| GET    | `/api/cases/:id`         | Case detail                                   |
| GET    | `/api/cases/metrics/summary` | Aggregated counts                           |
| GET    | `/api/cases/metrics/timeline`| Time-series counts (days query param)       |
| GET    | `/api/cases/history/recent`  | Latest case history entries (limit, hours)  |
| POST   | `/api/cases`             | Create new case (requires `x-api-key` if set) |
| PATCH  | `/api/cases/:id`         | Update status / assign team (requires API key) |

## Notes

- Set `API_KEY` in `.env` to protect mutating endpoints.
- `MODEL_API_URL` (optional) should point to inference service returning priority/risk/resource predictions.
